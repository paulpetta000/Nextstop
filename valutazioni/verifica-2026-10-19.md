# Verifica del laboratorio · 19/10/2026

Flusso provato: apertura di una scheda inventata → scelta della singola piattaforma → caricatore simulato → validazione di media/conteggio → fascia sotto la foto. La prova non passa da un’API reale: nessun account disponibile e nessuna spesa attivata.

| Verifica eseguita | Esito e limite |
|---|---|
| Dieci test del modello | Passati: dati mancanti, conteggio zero, scale, identità, duplicati, annullamento, risposte vecchie, scadenza, quota ed errori separati |
| 118 asserzioni nel browser Chromium | Passate: flussi principali e casi limite, su telefono/desktop e temi chiaro/scuro; nessun errore console o richiesta esterna |
| Ultimo controllo della disposizione | Sei combinazioni 320/390/1280 px × chiaro/scuro: nessuno scorrimento orizzontale, collegamenti dei voti con altezza almeno 44 px |
| Contrasti CSS controllati | Dieci coppie di colori espliciti: rapporto minimo 5,65; non è un audit automatico completo |
| Identità e metadati | Quattro ID interni esistenti; quattro candidati Tripadvisor distinti, un profilo di altra sede escluso; un link Google dal gestore, zero Place ID confermati; nessun voto reale conservato |
| Conservazione | Nessuna modifica a `src/`, `public/`, dipendenze, configurazione o procedure degli orari |
| Test/build/link dell’applicazione | Verifica completa affidata alla CI della PR sul ramo; leggere il risultato del commit corrente, non dedurlo da questo rapporto |
| Axe e Lighthouse | Non eseguiti: strumenti non presenti e nessuna installazione aggiunta. Restano necessari secondo le regole del progetto prima di un’anteprima del prodotto |
| Componenti e servizi reali | Non provati: nessuna conclusione su resa del UI Kit, campi effettivi dei singoli profili, costo fatturato, diritti o comportamento degli SDK |

Correzioni guidate dalle prove: conteggi italiani coerenti; chiusura immediata senza avvio del caricatore; focus mantenuto durante l’attesa e spostato sul link al risultato soltanto se ancora sul relativo comando; risposte annullate senza contaminare la scheda successiva.

Per ripetere i test del modello:

```sh
node --test test/valutazioni-laboratorio.test.mjs
```

Nel runner cloud locale è stato necessario usare `--test-isolation=none` per osservare i risultati del processo Node; il test non richiede dipendenze. La CI usa il comando ordinario del progetto.
